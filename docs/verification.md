## 2. Дефекты, найденные при проверке

### 2.1. Бесконечная рекурсия в риск-движке (найдено unit-тестами)

`StackOverflowError` в 12 из 14 тестов `RiskEngineTest`.

**Причина.** `assess()` вызывал `suggestSubstitutes()`, который для каждого продукта-кандидата
снова вызывал `assess()` — и так до переполнения стека. Аналогично `portionAdvice()` перебирал
порции через `assess()`.

**Исправление.** Расчёт баллов вынесен в приватный метод `core()`, который не вызывает сам себя.
`assess()`, `portionAdvice()`, `suggestSubstitutes()` и `assessMeal()` надстроены над `core()`.

### 2.2. `\w` не включает кириллицу (найдено unit-тестами)

Тест «разбирает полную русскую этикетку» падал: поле «насыщенные жиры» оказывалось нулевым,
а «лимонная кислота» не давала тег кислоты.

**Причина.** В Java/Kotlin `\w` по умолчанию означает `[a-zA-Z0-9_]`. Шаблон `жирн\w*\s+кислот\w*`
не находил «жирные кислоты», поэтому фраза не маскировалась, и следующее слово «жир» обрывало
поиск значения у поля «насыщенные жиры». Шаблон `лимонн\w*\s+кислот\w*` по той же причине
не срабатывал на «лимонная кислота».

**Исправление.** Явные Unicode-классы `[\p{L}\p{N}_]` вместо `\w` (см. пункт 2.3 о том, почему
нельзя было просто включить флаг).

### 2.3. Android отвергает флаг `(?U)` — приложение падало (найдено на эмуляторе)

Первый вариант исправления включал флаг `(?U)` (`UNICODE_CHARACTER_CLASS`). На настольной JVM
это работало, все 52 теста проходили. Но при открытии экрана «КБЖУ по этикетке» на Android
приложение мгновенно закрывалось:

```
java.util.regex.PatternSyntaxException: Syntax error in regexp pattern near index 3
(?U)\d+(?:\.\d+)?
   ^
    at com.gastrocare.compass.domain.engine.LabelTextParser$Companion.rx(LabelTextParser.kt:641)
    at ...LabelTextParser.<clinit>(LabelTextParser.kt:643)
```

**Причина.** Android использует ICU-реализацию регулярных выражений, в которой флага `U` нет
(там `u` означает совсем другое — `UNICODE_CASE`). Ошибка возникала в статическом инициализаторе
класса, то есть при первом обращении к парсеру — отсюда немедленное закрытие приложения.
При этом `\w` в ICU уже Unicode-aware, поэтому на Android проблема 2.2 не проявлялась —
именно поэтому её нельзя было поймать только unit-тестами.

**Исправление.** Флаги убраны полностью, кириллица задаётся явными классами `\p{L}`, а границы
слов `\b` заменены на переносимые lookaround `(?![\p{L}\p{N}])` — потому что `\b` на JVM и Android
определяется по-разному при разных флагах.

**Защита от повторения.** Добавлен тест `в шаблонах нет флагов, не поддерживаемых Android`:
он читает исходный файл парсера и падает, если в коде появятся `(?U)`, `\w` или `\b`.

### 2.4. «Лимонная кислота» определялась как цитрусовые (найдено на эмуляторе)

На экране этикетки продукт с регулятором кислотности получал «риск 92/100 — избегать»
и подпись «в составе цитрусовые компоненты».

**Причина.** Шаблон цитрусовых `лимон\w*` срабатывал на слова «лимонная» в составе
«регулятор кислотности (лимонная кислота)». У пользователя с личным триггером «цитрусовые»
такой продукт сразу попадал в красную зону и в «полный запрет».

**Исправление.** Перед проверкой на цитрусовые из текста состава удаляются фразы, распознанные
как кислотные регуляторы. Настоящие цитрусовые ингредиенты («апельсиновый сок») по-прежнему
определяются. Добавлены два теста на оба случая.

### 2.5. Проблемы сборочного окружения (не дефекты приложения)

Пришлось решить четыре инфраструкментные задачи, они описаны в README:

* AGP блокирует путь с кириллицей → `android.overridePathCheck=true`;
* внешний Kotlin-демон не может писать в `%LOCALAPPDATA%\kotlin` и ломается на не-ASCII путях
  → `kotlin.compiler.execution.strategy=in-process`;
* JVM-воркер тестов не грузит классы из пути с кириллицей → тесты запускаются в ASCII-зеркале
  (`tools/build.ps1`);
* AGP не может создать `~/.android/debug.keystore` → подпись задана ключом внутри проекта.

## 3. Воспроизведение проверки

```powershell
# 1. Тесты и сборка APK (в ASCII-зеркале, офлайн)
powershell -ExecutionPolicy Bypass -File tools/build.ps1

# 2. Установка на подключённое устройство или эмулятор
adb install -r dist\GastroCompass-debug.apk

# 3. Демонстрационные данные: профиль с ГЭРБ и гастритом, дневник, симптомы, взвешивания
powershell -ExecutionPolicy Bypass -File tools/seed-demo-data.ps1

# 4. Проверка экрана этикетки вручную:
#    «Сегодня» → прокрутить → «Этикетка» → «Пример» → «Разобрать»
```

## 4. Что осталось непроверенным

* Реальные устройства с Android 7–13 (проверялся Android 15): использованы только стабильные
  API, но полный прогон на старых версиях не выполнялся.
* Фото этикетки (OCR), штрихкод и голосовой ввод — не реализованы, описаны как план.
* Сценарии с очень большими дневниками (сотни записей) — производительность не измерялась.
* Медицинская валидация весов факторов специалистом не проводилась: логика основана
  на общих клинических принципах, а не на клиническом исследовании приложения.
